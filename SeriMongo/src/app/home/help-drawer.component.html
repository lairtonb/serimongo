Help - SeriMongo

User manual

Overview

Inspect logs in real time or from a stable search result.

SeriMongo combines SignalR Tail, LogQL search, quick filters and structured details so you can analyze events without leaving the page.

Main flow

Use filters and the query to narrow the result set, select a row to open details, then copy what you need for incidents, PRs or tickets.

Search

LogQL input and Search action

Type a LogQL expression in the main field. Clicking Search pauses Tail and loads a stable page of results.

The Effective query panel shows the final query produced by combining the typed expression with the selected period, level and service filters.

LogQL

Supported syntax

Fields

id, timestamp, time, level, message, renderedmessage, exception, service, servicename, service.name.

Properties

Use prop.<name>, property.<name> or properties.<name> for structured fields. Dotted paths are supported. Use exists to check whether a property is present.

Operators

=, !=, >, >=, <, <=, contains, startswith, endswith, in (...) and exists.

Boolean logic

Combine conditions with and, or and parentheses.

level = Error
level in (Warning, Error, Fatal)
message contains "timeout"
message startswith "checkout"
exception contains "OutOfMemoryException"
serviceName = "checkout-api"
timestamp >= "2026-06-25T12:00:00Z"
prop.TraceId = "abc123"
prop.exception.type exists
prop.DurationMs > 500
(level = Error or level = Fatal) and serviceName = "worker"

There is no isNull, isTrue or isFalse operator today. For boolean or null checks, write manual LogQL only after the query syntax supports the exact predicate you need.

Quick filters

Period, level and service

Quick filters build LogQL clauses automatically. Period creates a timestamp condition; selected levels create level in (...); selected services create serviceName in (...).

Property quick filters can be added from the selected event details. They use = and currently support only string and number values with simple property keys.

The Clear button resets quick filters while keeping the expression typed in the LogQL field.

Table

Rows, columns and selection

The table is virtualized to keep the UI responsive with many logs. Click a row to open the details panel.

The columns button lets you show or hide TraceId, Timestamp, Level, Service and Message. At least one column always remains visible.

Details

Selected event

The side panel shows message, timestamp, service, id, exception and properties. The splitter between the table and details can be dragged to resize the panel.

Use the funnel button on a property card to add that string or number property as a quick filter without pausing Tail.

Selecting a row pauses Tail so new events do not change the context while you inspect the record.

Copy

Clipboard and Markdown

Use the copy button in the details header to export the event as Markdown. The buttons in Message and Exception copy only that block.

After a copy action, a toast appears in the lower-right corner confirming success or failure.

Tail

Pause and resume

Pause does not disconnect SignalR. It only sends the paused state to the hub and blocks new events from being added to the screen.

After pausing, the button label changes back to Tail. Clicking it re-enables Tail on the same SignalR connection and syncs the current query with the hub.
