## Comportamento Esperado

- Clicar em `Search` pausa Tail.
- Selecionar uma linha da tabela pausa Tail.
- Clicar novamente na linha selecionada apenas desmarca a linha; não reativa Tail.
- Clicar em `Tail` reativa Tail com a query atual.
- Clicar em filtro de Log Level não deve pausar Tail.
- Clicar em filtro de Service Name não deve pausar Tail.
- Clicar em filtro de período não deve pausar Tail.
- Clicar em `Clear` nos Quick Filters não deve pausar Tail.
- Quando Tail está ativo e um filtro muda, a query do Tail é atualizada via SignalR.
- Quando Tail está pausado e um filtro muda, a lista é atualizada por busca HTTP, mas Tail continua pausado.

## Decisões De UI

- A tela deve ser densa e técnica, não espaçada como dashboard genérico.
- A command bar compacta é a direção aprovada para resolver o mau uso do espaço.
- Evitar voltar ao painel alto de busca com `Window`, textarea e botões em duas linhas.
- O LogQL na command bar deve permanecer baixo, de uma linha visual.
- O antigo `controlHeight(search)` foi removido do textarea compacto para ele não crescer.
- Quick Filters devem continuar com grupos visuais claros (`Log Level`, `Service Name`).
- A sidebar não deve ganhar redesign amplo sem necessidade.
- ZardUI segue fora; usar CSS customizado.
- Evitar dependência de icon library só por chevron; o chevron atual é SVG inline.

## Validação Usada

Use Node 24 via Docker para builds Angular do app principal:

```powershell
docker run --rm --mount "type=bind,source=C:\Projetos\serimongo\SeriMongo,target=/app" -w /app node:24-alpine npm run build
```

Build .NET do app principal:

```powershell
dotnet build "SeriMongo\SeriMongo.csproj"
```

Rebuild e restart do app principal em Docker:

```powershell
docker compose build serimongo
docker compose up -d serimongo
```
